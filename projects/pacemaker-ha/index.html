Pacemaker + httpd 웹 서비스 HA 구성

Pacemaker와 Corosync로 2노드 Active/Standby 클러스터를 만들고, VIP와 httpd를 묶어 장애 시 자동으로 전환되도록 구성했습니다.

1. 구성 개요

OSRocky Linux 9
노드node1 10.0.0.11 / node2 10.0.0.12
VIP10.0.0.100/24
클러스터web-cluster (Active/Standby)
리소스 그룹grp_web = res_vip (IPaddr2) + res_httpd (systemd:httpd)
 
클라이언트 ──▶ VIP 10.0.0.100
                 │
        ┌────────┴────────┐
     node1 (Active)    node2 (Standby)
     res_vip           ← 장애 시 이동
     res_httpd         ← 장애 시 이동
        └──── Corosync 하트비트 ────┘

2. 사전 준비 (양쪽 노드)

# 호스트 이름
cat >> /etc/hosts << 'EOF'
10.0.0.11 node1
10.0.0.12 node2
EOF

# HA 저장소 활성화 (Rocky 9 기본 비활성)
dnf config-manager --set-enabled highavailability

# 패키지 설치
dnf install -y pacemaker corosync pcs fence-agents-all httpd

# pcsd 시작
systemctl enable --now pcsd

# httpd는 Pacemaker가 제어하므로 systemd 자동 시작은 끔
systemctl disable --now httpd

# 클러스터 관리 계정 비밀번호 (양쪽 동일)
passwd hacluster

# 방화벽
firewall-cmd --permanent --add-service=high-availability
firewall-cmd --permanent --add-service=http
firewall-cmd --reload

3. 클러스터 생성 (node1에서)

# 노드 인증
pcs host auth node1 node2 -u hacluster

# 클러스터 생성 및 시작
pcs cluster setup web-cluster node1 node2 --start --enable

# 실습 환경: 펜싱 장치가 없어 STONITH 비활성화
pcs property set stonith-enabled=false

pcs status

4. 리소스 구성

# VIP
pcs resource create res_vip IPaddr2 ip=10.0.0.100 cidr_netmask=24 op monitor interval=10s

# httpd
pcs resource create res_httpd systemd:httpd op monitor interval=10s

# 같은 노드에서 VIP → httpd 순서로 동작하도록 그룹화
pcs resource group add grp_web res_vip res_httpd
* Resource Group: grp_web:
  * res_vip   (ocf:heartbeat:IPaddr2):  Started node1
  * res_httpd (systemd:httpd):          Started node1

5. Failover 테스트

# 클라이언트: VIP 접속 확인
curl http://10.0.0.100

# node1을 Standby로 전환 (장애 시뮬레이션)
pcs node standby node1
pcs status
#   * res_vip   → Started node2
#   * res_httpd → Started node2

# 클라이언트: 같은 VIP로 계속 접속되는지 확인
curl http://10.0.0.100

# node1 복구
pcs node unstandby node1

복구 후에도 리소스는 자동으로 node1로 돌아오지 않습니다(Auto Failback 없음). 원래 노드로 옮기려면 수동으로 이동합니다.

pcs resource move grp_web node1
pcs resource clear grp_web   # 이동 시 생긴 위치 제약 제거

6. 트러블슈팅: pcs 설치 시 ruby 모듈 충돌

  • 증상: dnf install pcs 시 ruby 모듈 필터링으로 의존성 해결 실패
  • 조치: ruby 모듈 스트림을 초기화·비활성화한 뒤 --nobest로 설치
dnf module reset ruby -y
dnf module disable ruby -y
dnf install -y python3-tornado python3-cryptography python3-pyparsing nss-tools
dnf install -y pcs --nobest

7. 운영 명령어 및 주의사항

pcs status                     # 전체 상태
pcs config                     # 설정 확인
pcs resource restart grp_web   # 리소스 재시작
journalctl -u pacemaker -f     # Pacemaker 로그
journalctl -u corosync -f      # Corosync 로그
  • httpd 자동 시작 금지: systemd에서 httpd를 enable하면 부팅 시 양쪽 노드에서 동시에 뜰 수 있습니다. 시작·정지는 Pacemaker에만 맡깁니다.
  • STONITH: 운영 환경에서는 반드시 펜싱 장치(IPMI, 하이퍼바이저 fence 등)를 구성해야 양쪽이 동시에 Active가 되는 split-brain을 막을 수 있습니다.
  • 콘텐츠 동기화: 두 노드의 웹 콘텐츠와 설정은 rsync나 공유 스토리지로 맞춰야 Failover 후에도 같은 화면이 나옵니다.
