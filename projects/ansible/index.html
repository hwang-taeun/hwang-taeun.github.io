Ansible 서버 자동화

여러 서버에 같은 작업을 반복하지 않도록, Ansible 플레이북으로 패키지 설치·서비스 기동·파일 배포·cron 등록을 자동화했습니다.

1. 설치 및 기본 설정

dnf install -y ansible-core

인벤토리 (/etc/ansible/hosts)

관리 대상 서버를 그룹으로 묶습니다. 접속은 비밀번호 대신 SSH 키를 사용합니다.

[file_servers]
fs01 ansible_host=10.0.0.31
fs02 ansible_host=10.0.0.32

[file_servers:vars]
ansible_user=deploy
# 제어 노드에서 키 생성 후 대상 서버에 배포
ssh-keygen -t ed25519
ssh-copy-id deploy@10.0.0.31
ssh-copy-id deploy@10.0.0.32

설정 파일 (/etc/ansible/ansible.cfg)

[defaults]
inventory = /etc/ansible/hosts      # 기본 인벤토리
remote_user = deploy                # 기본 접속 계정
host_key_checking = True            # 처음 접속 시 호스트 키 확인 (보안)

연결 테스트

ansible file_servers -m ping

2. 플레이북: Apache 설치 및 기동

# install_apache.yml
- name: Install and start Apache          # 작업 설명
  hosts: file_servers                     # 대상 그룹
  become: true                            # root 권한으로 실행
  tasks:
    - name: Install Apache
      ansible.builtin.dnf:
        name: httpd
        state: present                    # 없으면 설치

    - name: Start and enable Apache
      ansible.builtin.service:
        name: httpd
        state: started                    # started / stopped / restarted
        enabled: true                     # 부팅 시 자동 시작

서비스 제어는 범용 service 모듈을 썼습니다. systemd 전용 기능(daemon_reload 등)이 필요하면 ansible.builtin.systemd_service 모듈을 사용합니다.

3. 플레이북: 백업 스크립트 배포 및 cron 등록

# crontab.yml
- name: Deploy backup script and register cron
  hosts: file_servers
  become: true
  tasks:
    - name: Copy backup script
      ansible.builtin.copy:
        src: ./files/backup.sh
        dest: /usr/local/bin/backup.sh
        mode: '0755'
        owner: root
        group: root

    - name: Create cron job for devops
      ansible.builtin.cron:
        name: "Run daily backup"          # 같은 이름이면 중복 등록하지 않음
        minute: "0"
        hour: "2"
        job: "/usr/local/bin/backup.sh"
        user: devops                      # 생략하면 become 때문에 root crontab에 등록

4. 실행 및 확인

# 변경 예정 내용만 미리 확인 (실제 변경 없음)
ansible-playbook install_apache.yml --check --diff

# 실제 적용
ansible-playbook install_apache.yml
ansible-playbook crontab.yml

# 결과 확인
ansible file_servers -m ansible.builtin.command -a "systemctl is-active httpd"
ansible file_servers -b -m ansible.builtin.command -a "crontab -l -u devops"

5. 운영 시 주의사항

  • 비밀번호를 인벤토리에 쓰지 않기: ansible_ssh_pass를 평문으로 두지 않고 SSH 키를 쓰며, 꼭 필요한 비밀값은 ansible-vault로 암호화합니다.
  • 호스트 키 확인 유지: host_key_checking = False나 StrictHostKeyChecking no는 중간자 공격을 막지 못하므로 실습에서만 사용합니다.
  • 멱등성: 모듈은 이미 원하는 상태면 아무것도 바꾸지 않으므로, 같은 플레이북을 여러 번 실행해도 안전합니다.
  • 접근 제한 환경: SSH 직접 접속이 막힌 서버에는 Ansible을 쓸 수 없어, 별도로 Pull 방식 배포를 구성했습니다. → CI/CD 프로젝트
