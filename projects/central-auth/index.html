시스템 인프라 운영

SSSD + LDAP/AD + RADIUS 중앙 인증

계정 정보(ID)와 비밀번호 검증(인증)을 분리해, 대규모 서버 환경(1000대 이상)에서 SSH 로그인을 중앙 계정으로 통합하는 구성입니다.

1. 아키텍처 개요

서버마다 로컬 계정을 만들면 UID/GID와 비밀번호 정책이 서버마다 달라집니다. 계정 속성은 LDAP/AD에서, 비밀번호 검증은 RADIUS에서 맡고, 각 서버는 SSSD로 두 결과를 합쳐 사용합니다.

사용자 ── SSH ──▶ WEB/DB 서버
                   sshd → PAM → SSSD
                                 ├─ 계정 조회 (id_provider)   ──▶ LDAP / AD
                                 └─ 비밀번호 검증 (auth)      ──▶ RADIUS ──▶ LDAP / AD

구성 요소 역할

구성 요소위치주요 기능관리 정보
LDAP / AD 중앙 서버 사용자 계정의 속성 정보를 제공하는 ID 공급자(ID Provider) UID, GID, 홈 디렉터리, 셸, 그룹
RADIUS 중앙 서버 입력한 비밀번호의 유효성을 검증하는 인증 서버 비밀번호, MFA(Multi-Factor Authentication)
SSSD WEB/DB 서버 중앙 서버의 ID·인증 정보를 통합하고 로컬에 캐싱하는 중개자 캐싱된 계정 속성과 인증 정보

2. 중앙 서버 설정

2.1 LDAP / AD (계정 속성)

  • LDAP 또는 AD 서버를 구축하고 서비스를 시작합니다.
  • 모든 사용자의 uidNumber, gidNumber, homeDirectory, loginShell 속성을 등록합니다. 서버마다 같은 UID/GID가 나오도록 여기서만 관리합니다.

2.2 RADIUS (FreeRADIUS, 비밀번호 검증)

로그인 시 입력한 비밀번호가 맞는지 LDAP/AD에 질의해 검증합니다.

# 패키지 설치
dnf install -y freeradius freeradius-utils freeradius-ldap

클라이언트 등록: 인증을 요청할 WEB/DB 서버와 공유 비밀키를 등록합니다.

# /etc/raddb/clients.conf
client web-servers {
    ipaddr = 192.0.2.0/24
    secret = [공유 비밀키]
}

LDAP 연동: ldap 모듈을 켜고 LDAP/AD 서버 정보를 넣습니다. AD는 비밀번호 해시를 내주지 않으므로 사용자 계정으로 LDAP bind를 시도하는 방식(Auth-Type LDAP)으로 검증합니다.

ln -s ../mods-available/ldap /etc/raddb/mods-enabled/ldap

# /etc/raddb/mods-enabled/ldap (주요 항목)
ldap {
    server   = 'ldap.example.com'
    identity = 'cn=radius,ou=service,dc=example,dc=com'
    password = '[서비스 계정 비밀번호]'
    base_dn  = 'dc=example,dc=com'
}

방화벽 및 서비스 시작

firewall-cmd --permanent --add-service=radius
firewall-cmd --reload

systemctl enable --now radiusd

# 서버에서 직접 인증 테스트
radtest taeun '[비밀번호]' 127.0.0.1 0 testing123

3. WEB/DB 서버 설정 (클라이언트)

3.1 패키지 설치

pam_radius는 EPEL 저장소에 있습니다.

dnf install -y epel-release
dnf install -y sssd sssd-tools pam_radius oddjob-mkhomedir

3.2 SSSD 설정

계정 조회는 LDAP으로, 비밀번호 검증은 proxy를 거쳐 RADIUS로 보냅니다. SSSD에는 RADIUS 전용 인증 공급자가 없어서, PAM 모듈(pam_radius_auth)을 proxy로 연결합니다.

# /etc/sssd/sssd.conf
[sssd]
domains = central
services = nss, pam

[domain/central]
# --- 계정 속성: LDAP/AD ---
id_provider = ldap
ldap_uri = ldaps://ldap.example.com
ldap_search_base = dc=example,dc=com
ldap_schema = rfc2307bis          # AD는 ad

# --- 비밀번호 검증: proxy → RADIUS ---
auth_provider = proxy
proxy_pam_target = sssd-radius

access_provider = permit
cache_credentials = true          # 중앙 서버 장애 시 캐시로 로그인 유지
chmod 600 /etc/sssd/sssd.conf      # 권한이 600이 아니면 SSSD가 시작되지 않음

3.3 RADIUS 연결 설정

# /etc/pam.d/sssd-radius  (proxy_pam_target 이 가리키는 PAM 스택)
auth     required   pam_radius_auth.so
account  required   pam_permit.so
# /etc/raddb/server  (pam_radius 가 사용할 RADIUS 서버)
# 서버[:포트]          공유 비밀키        타임아웃(초)
192.0.2.10:1812       [공유 비밀키]      3
chmod 600 /etc/raddb/server

3.4 PAM 연동 및 서비스 시작

/etc/pam.d/sshd를 직접 고치지 않고 authselect로 SSSD 프로필을 적용합니다. 첫 로그인 시 홈 디렉터리도 자동으로 만들어집니다.

authselect select sssd with-mkhomedir --force
systemctl enable --now oddjobd
systemctl enable --now sssd

4. 동작 확인

# 계정 조회 (LDAP/AD)
getent passwd taeun
id taeun

# SSSD 도메인 상태
sssctl domain-status central

# 최종 테스트: 중앙 계정으로 SSH 로그인 (비밀번호 → RADIUS 검증)
ssh taeun@web01

로그인이 실패하면 /var/log/sssd/와 /var/log/secure, RADIUS 서버의 radiusd -X(디버그 모드)로 어느 단계에서 막히는지 확인합니다.

5. 설계 포인트

  • 역할 분리: 계정 속성(LDAP/AD)과 비밀번호 검증(RADIUS)을 나눠, RADIUS 쪽에 MFA를 붙여도 서버 설정은 바뀌지 않습니다.
  • SSSD proxy 사용: SSSD는 RADIUS를 직접 지원하지 않으므로 auth_provider = proxy로 pam_radius_auth를 연결했습니다.
  • 장애 대비: cache_credentials로 중앙 서버가 잠시 내려가도 한 번 로그인했던 계정은 캐시로 로그인할 수 있습니다.
  • 비밀값 관리: 공유 비밀키와 서비스 계정 비밀번호가 들어간 파일은 모두 600 권한으로 제한합니다.
