접근제어 환경의 CI/CD 배포 자동화

서버로 직접 접속할 수 없는 환경에서, 서버가 CI/CD 서버로 작업을 가지러 오는 Pull 방식으로 다수 서버 일괄 작업을 자동화했습니다.

1. 환경 제약

제약내용
SSH 직접 접속 불가운영 서버는 서버 접근제어를 통해서만 SSH 접속 가능
방화벽SSH(22)는 접근제어 IP만 허용, CI/CD 서버와는 80/443만 통신 가능
에이전트 설치 제한Woodpecker Agent 같은 별도 데몬이나 HTTP API 설치 불가

CI/CD 서버가 운영 서버로 접속하는 Push 방식은 쓸 수 없으므로, 운영 서버가 CI/CD 서버로 HTTP 요청을 보내는 Pull 방식을 선택했습니다. 운영 서버에는 bash, curl, git만 있으면 됩니다.

2. 아키텍처

[CI/CD 서버 (Master) 10.0.0.10]            [운영 서버 (Agent) 10.0.0.21 ...]
  Podman                                      polling_agent.sh (cron 1분)
  ├─ Gitea      :3000  (작업·로그 저장)              │
  └─ Job API    :80    (httpd CGI)                   │
        ◀──────────── 1) GET  /cgi-bin/get_jobs.sh ──┤
                       2) 작업 실행                   │
        ◀──────────── 3) POST /cgi-bin/post_result.sh┤
  Gitea ◀──────────── 4) 실행 로그 push ─────────────┘
                     (모두 80/443 아웃바운드 HTTP)

3. CI/CD 서버 구성

Gitea 컨테이너

dnf install -y podman
mkdir -p /opt/gitea/data
chown -R 1000:1000 /opt/gitea/data

podman run -d --name gitea --restart=always \
  -p 3000:3000 -p 222:22 \
  -v /opt/gitea/data:/data:Z \
  -e GITEA__server__ROOT_URL=http://10.0.0.10:3000/ \
  docker.io/gitea/gitea:latest

웹 화면에서 관리자 계정을 만들고 로그 저장용 cicd-logs 저장소를 생성한 뒤, Settings → Applications에서 API 토큰을 발급합니다.

Job API (httpd CGI)

mkdir -p /opt/cicd/{jobs,results,logs,cgi-bin}

# /opt/cicd/cgi-bin/get_jobs.sh : jobs 폴더의 JSON을 배열로 반환
#!/bin/bash
echo 'Content-Type: application/json'
echo ''
first=true
echo '['
for f in /opt/cicd/jobs/*.json; do
    [ -f "$f" ] || continue
    $first || echo ','
    cat "$f"
    first=false
done
echo ']'

# /opt/cicd/cgi-bin/post_result.sh : Agent가 보낸 결과 저장
#!/bin/bash
echo 'Content-Type: application/json'
echo ''
read -r -n "$CONTENT_LENGTH" POST_DATA
echo "$POST_DATA" > "/opt/cicd/results/result_$(date +%Y%m%d_%H%M%S)_$$.json"
echo '{"status":"ok"}'
chmod +x /opt/cicd/cgi-bin/*.sh

# 공식 httpd 이미지의 cgi-bin 경로에 스크립트를 연결
podman run -d --name cicd-api --restart=always -p 80:80 \
  -v /opt/cicd/cgi-bin:/usr/local/apache2/cgi-bin:Z \
  -v /opt/cicd/jobs:/opt/cicd/jobs:Z \
  -v /opt/cicd/results:/opt/cicd/results:Z \
  docker.io/library/httpd:2.4

# CGI 모듈 활성화 (event MPM은 cgid, prefork는 cgi)
podman exec cicd-api sed -i \
  -e 's/^\s*#\s*LoadModule cgid_module/LoadModule cgid_module/' \
  -e 's/^\s*#\s*LoadModule cgi_module/LoadModule cgi_module/' \
  /usr/local/apache2/conf/httpd.conf
podman restart cicd-api

작업(Job) 정의

# /opt/cicd/jobs/job_001.json
{
  "job_id": "job_001",
  "description": "hostname 출력 테스트",
  "commands": [
    "echo === CI/CD Job 실행 ===",

4. 운영 서버: Polling Agent

1분마다 작업 목록을 가져와, 아직 실행하지 않은 작업만 실행하고 결과를 CI/CD 서버와 Gitea에 보냅니다.

#!/bin/bash
# /opt/cicd/polling_agent.sh
MASTER_URL="http://10.0.0.10"
GITEA_URL="http://10.0.0.10:3000"
GITEA_REPO="admin/cicd-logs"
GITEA_TOKEN=$(</etc/cicd/gitea.token)     # 토큰은 별도 파일(600)로 분리
STATE_DIR="/opt/cicd/state"
LOG_DIR="/opt/cicd/agent_logs"
HOST=$(hostname)
mkdir -p "$STATE_DIR" "$LOG_DIR"

JOBS=$(curl -s --max-time 10 "$MASTER_URL/cgi-bin/get_jobs.sh")
[ -z "$JOBS" ] || [ "$JOBS" = "[]" ] && exit 0

# 작업 ID 목록
for JOB_ID in $(echo "$JOBS" | python3 -c 'import sys,json; [print(j["job_id"]) for j in json.load(sys.stdin)]'); do
    [ -f "$STATE_DIR/$JOB_ID.done" ] && continue   # 이미 실행한 작업은 건너뜀

    TS=$(date +%Y%m%d_%H%M%S)
    LOG_FILE="$LOG_DIR/${JOB_ID}_${HOST}_${TS}.log"

    # 해당 작업의 명령을 한 줄에 하나씩 꺼내 순서대로 실행
    {
        echo "[$(date)] Job 시작: $JOB_ID ($HOST)"
        echo "$JOBS" | python3 -c '
import sys, json
jid = sys.argv[1]
for j in json.load(sys.stdin):
    if j["job_id"] == jid:
        print("\n".join(j["commands"]))' "$JOB_ID" |
        while IFS= read -r CMD; do
            echo "[CMD] $CMD"
            bash -c "$CMD" 2>&1
        done
        echo "[$(date)] Job 완료: $JOB_ID"
    } > "$LOG_FILE"

    LOG_B64=$(base64 -w0 "$LOG_FILE")

    # 결과를 CI/CD 서버로 전송
    curl -s -X POST "$MASTER_URL/cgi-bin/post_result.sh" \
        -H 'Content-Type: application/json' \
        -d "{\"job_id\":\"$JOB_ID\",\"host\":\"$HOST\",\"log\":\"$LOG_B64\"}" >/dev/null

    # 실행 로그를 Gitea 저장소에 파일로 기록
    curl -s -X POST "$GITEA_URL/api/v1/repos/$GITEA_REPO/contents/agent-logs/$(basename "$LOG_FILE")" \
        -H "Authorization: token $GITEA_TOKEN" \
        -H 'Content-Type: application/json' \
        -d "{\"message\":\"Agent log: $JOB_ID from $HOST\",\"content\":\"$LOG_B64\"}" >/dev/null

    touch "$STATE_DIR/$JOB_ID.done"
done
chmod 700 /opt/cicd/polling_agent.sh

# crontab -e (1분마다)
* * * * * /opt/cicd/polling_agent.sh >> /opt/cicd/agent_logs/cron.log 2>&1

5. 테스트

# CI/CD 서버: API 응답 확인
curl -s http://localhost/cgi-bin/get_jobs.sh
# [{"job_id":"job_001", ...}]

# 운영 서버: Agent 수동 실행 후 로그 확인
bash /opt/cicd/polling_agent.sh
grep -A1 '\[CMD\] hostname' /opt/cicd/agent_logs/*.log

여러 서버에 Agent를 두고 같은 작업을 넣으면, Gitea cicd-logs/agent-logs/에 서버별 로그가 따로 쌓입니다.

agent-logs/
├── job_test_web-server-01_20260504_120000.log
├── job_test_web-server-02_20260504_120001.log
└── job_test_db-server-01_20260504_120002.log

7. 보안 고려사항 및 개선 방향

Agent는 받아온 명령을 그대로 실행하므로, Job API를 조작할 수 있으면 모든 서버에서 명령이 실행될 수 있습니다. 운영 적용 시 다음을 함께 적용해야 합니다.

  • HTTPS: Job API와 Gitea를 HTTPS로 제공해 전송 중 변조를 막습니다.
  • 인증·서명: Job API에 토큰 인증을 두거나, 작업 파일에 서명을 붙여 Agent가 검증한 뒤 실행합니다.
  • 최소 권한: Agent를 root가 아닌 전용 계정으로 실행하고, 필요한 명령만 sudo로 허용합니다.
  • 작업 관리: 작업 파일을 Gitea 저장소(cicd-jobs)로 관리하면 누가 어떤 작업을 넣었는지 이력이 남습니다.
