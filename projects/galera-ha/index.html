MariaDB Galera Active-Active HA 구성

MariaDB Galera Cluster로 두 노드 모두 읽기·쓰기가 가능한 DB 이중화를 구성하고, 구축 과정에서 실제로 발생한 에러와 해결 방법을 정리했습니다.

1. 구성 환경

OSRHEL 9 / Rocky Linux 9
DBMariaDB 10.11 + Galera 4 (26.4)
노드node1 10.0.0.11 / node2 10.0.0.12
SST 방식rsync
포트3306 (MariaDB), 4567 (Galera 복제), 4568 (IST), 4444 (SST)

Active-Active와 Active-Standby 비교

구분Active-Active (Galera)Active-Standby (복제)
쓰기모든 노드 가능Primary만 가능
장애 시남은 노드가 바로 처리Standby를 Primary로 승격
AUTO_INCREMENT노드별로 분리 (1,3,5 / 2,4,6)순차 (1,2,3…)

AUTO_INCREMENT 값이 띄엄띄엄 생기는 것은 노드 간 키 충돌을 막기 위한 정상 동작입니다.

2. 사전 준비 (양쪽 노드)

방화벽

firewall-cmd --permanent --add-port=3306/tcp            # MariaDB
firewall-cmd --permanent --add-port=4567/tcp --add-port=4567/udp   # Galera 복제
firewall-cmd --permanent --add-port=4568/tcp            # IST (증분 전송)
firewall-cmd --permanent --add-port=4444/tcp            # SST (전체 동기화)
firewall-cmd --reload

SELinux

SELinux enforcing 상태에서는 SST에 쓰는 rsync가 4444 포트를 열지 못합니다. 포트에 rsync 라벨을 붙여 해결합니다.

semanage port -m -t rsync_port_t -p tcp 4444

패키지 설치

cat > /etc/yum.repos.d/mariadb.repo << 'EOF'
[mariadb]
name = MariaDB
baseurl = https://downloads.mariadb.com/MariaDB/mariadb-10.11/yum/rhel9-amd64
gpgkey = https://downloads.mariadb.com/MariaDB/RPM-GPG-KEY-MariaDB
gpgcheck = 1
EOF

dnf install -y MariaDB-server MariaDB-client galera-4

3. Galera 설정

/etc/my.cnf.d/galera.cnf — 양쪽 노드에 적용하고, wsrep_node_address와 wsrep_node_name만 노드별로 바꿉니다.

[mysqld]
wsrep_on=ON
wsrep_provider=/usr/lib64/galera-4/libgalera_smm.so

# 클러스터 멤버와 이름 (양쪽 동일)
wsrep_cluster_address=gcomm://10.0.0.11,10.0.0.12
wsrep_cluster_name=my_galera_cluster

# 현재 노드 (노드마다 다르게)
wsrep_node_address=10.0.0.11
wsrep_node_name=node1

wsrep_sst_method=rsync

# Galera 필수 InnoDB 설정
binlog_format=ROW
default_storage_engine=InnoDB
innodb_autoinc_lock_mode=2

문자셋 (한글 지원)

기본값이 latin1이라 한글 입력 시 ERROR 1366 Incorrect string value가 발생했습니다. /etc/my.cnf.d/mariadb-server.cnf에 utf8mb4를 지정합니다.

[mysqld]
character-set-server = utf8mb4
collation-server = utf8mb4_general_ci

[client]
default-character-set = utf8mb4

4. 클러스터 기동

첫 노드는 galera_new_cluster로 클러스터를 새로 만들고, 나머지 노드는 일반 시작으로 합류시킵니다. 순서를 지키지 않으면 클러스터가 구성되지 않습니다.

# node1: 클러스터 부트스트랩
galera_new_cluster

# node2: node1 정상 확인 후 합류
systemctl start mariadb

# 양쪽: 부팅 시 자동 시작
systemctl enable mariadb

상태 확인

mysql -e "SHOW STATUS WHERE Variable_name IN
  ('wsrep_cluster_size','wsrep_cluster_status','wsrep_connected',
   'wsrep_ready','wsrep_local_state_comment');"
변수정상값의미
wsrep_cluster_size2연결된 노드 수
wsrep_cluster_statusPrimary쿼리를 처리할 수 있는 주 클러스터
wsrep_connected / wsrep_readyON연결 및 쿼리 처리 가능
wsrep_local_state_commentSynced동기화 완료

5. 동기화 테스트

-- node1: 테이블 생성 및 입력
CREATE DATABASE ha_test;
USE ha_test;
CREATE TABLE members (
  id INT AUTO_INCREMENT PRIMARY KEY,
  name VARCHAR(50) NOT NULL,
  created_at DATETIME DEFAULT NOW()
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
INSERT INTO members (name) VALUES ('홍길동'), ('김철수'), ('이영희');

-- node2: 같은 데이터가 보이면 성공 (id 1, 3, 5)
SELECT * FROM ha_test.members;

-- node2에서 입력 → node1에서 조회되면 양방향 복제 성공
INSERT INTO ha_test.members (name) VALUES ('박민수');

한 쪽에서 입력하고 다른 쪽에서 watch -n 1으로 조회하면 실시간으로 반영되는 것을 확인할 수 있습니다.

6. 트러블슈팅

rsync SST 포트 바인딩 실패

rsyncd: bind() failed: Permission denied (address-family 2)
rsyncd: unable to bind any inbound sockets on port 4444
  • 원인: SELinux가 rsync의 4444 포트 사용을 차단
  • 조치: semanage port -m -t rsync_port_t -p tcp 4444 후 MariaDB 재시작

부트스트랩 거부 (safe_to_bootstrap)

WSREP: It may not be safe to bootstrap the cluster
WSREP: wsrep::connect(gcomm://...) failed
Aborting
  • 원인: 비정상 종료로 grastate.dat의 safe_to_bootstrap이 0으로 남음
  • 조치: 가장 최신 데이터를 가진 노드(seqno가 큰 노드)를 확인해 그 노드에서만 값을 1로 바꾸고 부트스트랩
# 각 노드의 마지막 커밋 위치 확인
mysqld --wsrep-recover
cat /var/lib/mysql/grastate.dat

# seqno가 큰 노드에서만 실행
cp /var/lib/mysql/grastate.dat /var/lib/mysql/grastate.dat.bak
sed -i 's/safe_to_bootstrap: 0/safe_to_bootstrap: 1/' /var/lib/mysql/grastate.dat
galera_new_cluster

node2가 클러스터에 연결되지 않음

WSREP: Failed to establish connection: Connect (반복)
  • 원인: node1이 아직 부트스트랩되지 않은 상태에서 node2를 먼저 시작
  • 조치: node1을 galera_new_cluster로 먼저 기동한 뒤 node2 재시작

한글 입력 오류

ERROR 1366 (22007): Incorrect string value: '\xED\x99\x8D...' for column `name`
  • 원인: 서버 기본 문자셋 latin1
  • 조치: 설정 파일에 utf8mb4 지정, 이미 만든 DB·테이블은 ALTER ... CONVERT TO CHARACTER SET utf8mb4로 변환

7. 운영 시 주의사항

  • 재부팅 순서: 전체 재기동 시 safe_to_bootstrap: 1인 노드에서 galera_new_cluster → 클러스터 크기 1 확인 → 나머지 노드 시작 → 크기 2 확인 순서로 진행합니다.
  • 2노드의 한계: 노드가 2대뿐이면 네트워크가 끊겼을 때 어느 쪽도 과반을 얻지 못해 양쪽 모두 쓰기를 멈출 수 있습니다(split-brain 방지). 운영 환경에서는 3노드로 늘리거나 중재자 garbd를 추가합니다.
  • 접속 지점 단일화: 애플리케이션이 한 노드 IP에 고정되어 있으면 그 노드 장애 시 접속이 끊깁니다. HAProxy 또는 Keepalived VIP를 앞에 두어 완전한 HA를 구성합니다.
  • 로그: journalctl -u mariadb -f | grep -E "WSREP|synced|joined|error"
