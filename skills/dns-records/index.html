DNS 레코드 정리

도메인 운영에 쓰이는 주요 DNS 레코드의 의미와 사용 이유를 예시와 함께 정리했습니다.

1. A 레코드 (Address Record)

example.com.    IN  A  192.0.2.1
  • 의미: 도메인 이름을 IPv4 주소로 매핑합니다.
  • 사용 이유: 도메인 이름으로 웹사이트에 접근할 때 실제 서버의 IP 주소를 찾는 데 사용합니다.

2. AAAA 레코드 (IPv6 Address Record)

example.com.    IN  AAAA  2001:db8:85a3::8a2e:370:7334
  • 의미: 도메인 이름을 IPv6 주소로 매핑합니다.
  • 사용 이유: IPv6 네트워크 환경에서 도메인 이름으로 서버에 접근할 때 필요합니다.

3. MX 레코드 (Mail Exchange Record)

example.com.    IN  MX  10  mail.example.com.
  • 의미: 도메인의 메일을 처리할 메일 서버와 우선순위를 지정합니다. 10이 우선순위이며, 숫자가 작을수록 먼저 사용됩니다.
  • 사용 이유: 도메인으로 오는 메일을 어느 서버로 전달할지 결정합니다.

4. CNAME 레코드 (Canonical Name Record)

www.example.com.    IN  CNAME  example.com.
  • 의미: 한 도메인 이름을 다른 도메인 이름으로 연결합니다. 위 예시에서 www.example.com은 example.com의 별칭입니다.
  • 사용 이유: 여러 도메인 이름이 같은 서버를 가리켜야 할 때, IP 변경 시 한 곳만 수정하면 되어 관리가 편합니다.

5. TXT 레코드 (Text Record)

example.com.    IN  TXT  "v=spf1 include:mailhost.com ~all"
  • 의미: 도메인에 임의의 텍스트를 저장합니다. 위 예시는 SPF(Sender Policy Framework) 정책입니다.
  • 사용 이유: 도메인 소유 인증, 메일 스팸 방지 정책(SPF, DKIM, DMARC), 외부 서비스 연동(예: Google 도메인 인증) 등에 사용합니다.

6. NS 레코드 (Name Server Record)

example.com.    IN  NS  ns1.example.com.
  • 의미: 도메인을 책임지는 권한 있는 네임서버를 지정합니다.
  • 사용 이유: DNS 조회 요청을 어느 서버로 보낼지 결정하며, 도메인의 DNS 관리 주체를 나타냅니다.

7. SOA 레코드 (Start of Authority Record)

  • 의미: DNS 존의 기본 설정 정보를 담으며, 존의 권한 시작점을 나타냅니다.
  • 사용 이유: 존의 업데이트 주기, 관리자 연락처, 시리얼 번호 등을 담아 프라이머리·세컨더리 네임서버 간 일관성을 유지합니다.
@  IN  SOA  ns1.example.com.  hostmaster.example.com. (
        2023101501  ; Serial
        7200        ; Refresh
        1800        ; Retry
        1209600     ; Expire
        86400 )     ; Minimum TTL

항목 설명

  • ns1.example.com.: 이 존의 프라이머리 네임서버입니다.
  • hostmaster.example.com.: 관리자 연락처입니다. 메일 주소의 @를 .으로 바꿔 씁니다. (hostmaster@example.com)
  • 2023101501 Serial: 존 파일의 버전 번호입니다. 레코드를 바꿀 때마다 증가시켜야 세컨더리 네임서버가 변경을 감지하고 동기화합니다. 보통 YYYYMMDDnn 형식을 씁니다.
  • 7200 Refresh: 세컨더리 네임서버가 프라이머리에 변경 여부를 확인하는 주기(초)입니다.
  • 1800 Retry: Refresh 확인에 실패했을 때 다시 시도하기까지 기다리는 시간(초)입니다.
  • 1209600 Expire: 세컨더리가 이 시간(초) 동안 프라이머리와 동기화하지 못하면 존 정보를 더 이상 응답에 사용하지 않습니다.
  • 86400 Minimum TTL: 현재는 존재하지 않는 레코드에 대한 응답(NXDOMAIN)을 캐시하는 시간(초)으로 사용됩니다. (RFC 2308)

8. PTR 레코드 (Pointer Record)

1.2.0.192.in-addr.arpa.    IN  PTR  example.com.
  • 의미: IP 주소를 도메인 이름으로 매핑합니다. IP를 거꾸로 적고 in-addr.arpa를 붙인 이름을 사용하며, 역방향 조회에 쓰입니다.
  • 사용 이유: IP 주소로 서버의 도메인 이름을 찾을 때 사용합니다. 네트워크 진단, 로그 분석, 메일 서버의 스팸 필터링 등에 활용됩니다.

9. SRV 레코드 (Service Record)

_sip._tcp.example.com.    IN  SRV  10  50  5060  sipserver.example.com.
  • 형식: 우선순위(10) 가중치(50) 포트(5060) 대상 호스트
  • 의미: 특정 서비스가 동작하는 호스트와 포트를 지정합니다. 위 예시는 SIP(Session Initiation Protocol) 서버입니다.
  • 사용 이유: VoIP, 메신저, AD 같은 서비스가 접속할 서버 주소와 포트를 자동으로 찾는 데 사용합니다.

10. DNS 레코드를 사용하는 이유

DNS 레코드는 인터넷의 주소록 역할을 합니다. 도메인 이름을 IP 주소나 다른 도메인 이름으로 바꾸고, 메일 서버 위치를 지정하는 등 다양한 기능을 제공합니다. 덕분에 사용자와 시스템은 사람이 읽을 수 있는 도메인 이름으로 서버와 서비스에 접근할 수 있습니다. 또한 인터넷 자원의 관리와 구성을 쉽게 하고, 네트워크 보안과 메일 전송의 신뢰성을 높이는 데 기여합니다.
