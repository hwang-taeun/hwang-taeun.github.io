SPA(React) 새로고침 시 보던 화면이 유지되지 않는 문제

호스팅 고객이 React로 만든 사이트에서 F5를 누르면 보던 화면(목록 페이지, 선택한 탭, 입력 값)이 사라지고 첫 화면으로 돌아간다는 문의를 받았습니다. 고객은 서버 문제이니 호스팅 쪽에서 대응해야 한다고 했습니다. 원인을 구분하는 방법과 새로고침해도 화면이 유지되도록 하는 실제 수정 방법을 정리했습니다.

도메인, 경로, 화면 이름(example.com, /list, “목록 화면”)과 그림은 설명용 예시입니다. 서버 환경은 mod_rewrite가 없는 구버전 OS·Apache입니다.

1. 증상

메뉴를 눌러 목록 3페이지로 이동한 뒤 F5를 누르면 첫 화면이 나옵니다. 화면은 바뀌었는데 주소창은 계속 https://example.com/입니다.

2. 원인 — 화면 상태는 브라우저 메모리에만 있다

React는 지금 보고 있는 화면, 페이지 번호, 필터, 입력 값을 브라우저 메모리(JavaScript 변수, state)에 보관합니다. F5를 누르면 브라우저가 메모리를 모두 지우고 JS를 처음부터 다시 실행하므로 초기값인 첫 화면이 나옵니다. React의 기본 동작입니다.

  • 새로고침할 때 서버로 가는 것은 주소(URL)뿐입니다. 메모리의 화면 상태는 전송되지 않습니다.
  • 주소가 계속 /이면 첫 접속과 새로고침은 서버 입장에서 똑같은 요청입니다.
  • 그래서 OS, httpd 버전, 모듈, 설정과 관계없이 서버에서는 해결할 수 없습니다. 서버를 최신으로 바꿔도 결과는 같습니다.

3. 진단 — 주소창부터 본다

메뉴를 눌러 화면을 옮긴 뒤 주소창이 바뀌는지 확인합니다. 결과에 따라 책임이 나뉩니다.

URL=https://example.com
curl -sI "$URL/" | head -3
curl -sI "$URL/list" | head -3    # 주소가 바뀌는 앱일 때만

4. 해결 — 화면 상태를 새로고침해도 남는 곳에 저장

보던 화면을 유지하려면 상태를 메모리 밖(주소 또는 브라우저 저장소)에 두고, 페이지가 다시 열릴 때 그 값을 읽어 와야 합니다. 두 방법 모두 앱 코드만 고치며 서버 설정과 모듈이 필요 없습니다.

방법 A: 화면 상태를 주소에 넣기 (권장)

구버전 Apache는 mod_rewrite가 없어 /list 같은 경로를 처리하지 못합니다. 이럴 때는 쿼리스트링(/?view=list&page=3)이나 HashRouter(/#/list?page=3)를 쓰면 서버는 항상 /만 받으므로 설정 없이 동작합니다.

// 쿼리스트링에 화면 상태 저장: /?view=list&page=3
import { useSearchParams } from "react-router-dom";

function Board() {
  const [params, setParams] = useSearchParams();
  const view = params.get("view") || "home";
  const page = Number(params.get("page") || 1);

  return (
    <>
      <button onClick={() => setParams({ view: "list", page: 1 })}>목록</button>
      <button onClick={() => setParams({ view: "list", page: page + 1 })}>다음 페이지</button>
      {view === "home" && <Home />}
      {view === "list" && <List page={page} />}
    </>
  );
}
// 라우터 감싸기 — 구버전 서버라면 HashRouter (주소: /#/...)
import { HashRouter } from "react-router-dom";

root.render(
  <HashRouter>
    <App />
  </HashRouter>
);
  • 새로고침뿐 아니라 뒤로가기, 즐겨찾기, 링크 공유도 같은 화면으로 열립니다.
  • HashRouter는 주소에 #이 붙고 검색 노출(SEO)에 불리합니다. 관리자·회원 전용 화면은 문제가 없습니다.

방법 B: sessionStorage에 저장 (코드 수정이 가장 적음)

주소 구조를 바꾸기 어려우면, 기존 useState를 아래 훅으로 바꿉니다. 값이 바뀔 때마다 브라우저 저장소에 기록하고, 새로고침 후 시작할 때 읽어 옵니다.

// usePersistentState.js
import { useState, useEffect } from "react";

export function usePersistentState(key, initial) {
  const [value, setValue] = useState(() => {
    try {
      const saved = sessionStorage.getItem(key);
      return saved !== null ? JSON.parse(saved) : initial;
    } catch {
      return initial;
    }
  });

  useEffect(() => {
    try { sessionStorage.setItem(key, JSON.stringify(value)); } catch {}
  }, [key, value]);

  return [value, setValue];
}
// 변경 전
const [screen, setScreen] = useState("home");
const [page, setPage]     = useState(1);

// 변경 후 — 이름(key)만 붙이면 나머지 코드는 그대로
import { usePersistentState } from "./usePersistentState";
const [screen, setScreen] = usePersistentState("screen", "home");
const [page, setPage]     = usePersistentState("page", 1);

  • 비밀번호, 개인정보는 저장소에 넣지 않습니다. 같은 PC의 다른 스크립트가 읽을 수 있습니다.

5. 주소는 유지되는데 첫 화면이 나올 때 (앱 설정)

원인확인·해결
로그인 상태가 메모리에만 있음새로고침하면 로그아웃된 것으로 판단해 첫 화면(로그인)으로 보냄. 토큰을 쿠키·저장소에 두고, 토큰 복원이 끝난 뒤 로그인 여부를 판단
모든 경로를 /로 보내는 라우트<Route path="*" element={<Navigate to="/" />} />에 걸림 → 경로 오타, basename 확인
MemoryRouter 사용주소를 쓰지 않는 라우터 → HashRouter/BrowserRouter로 교체
시작할 때 첫 화면으로 이동하는 코드useEffect(() => navigate("/"), []) 같은 코드 제거
 
// 로그인 복원 예시 — 복원 전에는 판단하지 않음
const [user, setUser]   = useState(null);
const [ready, setReady] = useState(false);

useEffect(() => {
  const token = localStorage.getItem("token");
  if (token) setUser(decode(token));
  setReady(true);
}, []);

if (!ready) return <Loading />;          // 이게 없으면 F5 순간 "비로그인"으로 보고 첫 화면 이동
if (!user)  return <Navigate to="/login" />;

6. 서버 쪽 원인인 경우 — 302 리다이렉트

주소가 /list처럼 바뀌는 앱인데 F5 후 주소가 /로 바뀐다면 서버가 리다이렉트하는 것입니다. 개발자 도구 Network 탭에서 Preserve log를 켜고 F5를 누르면 확인할 수 있습니다.

mod_rewrite가 없는 구버전이라도 ErrorDocument는 Apache core 지시어라 모든 버전에 있습니다. 전체 URL을 쓰면 리다이렉트, 로컬 경로를 쓰면 주소를 유지한 채 내용만 전달합니다.

cd /etc/httpd
grep -rn "ErrorDocument" conf/ conf.d/ 2>/dev/null
# 원인 (주소가 /로 바뀜)
ErrorDocument 404 http://example.com/

# 수정 — 해당 사이트 문서 루트의 .htaccess (AllowOverride FileInfo 이상)
ErrorDocument 404 /index.html

이 방식은 화면은 정상이지만 응답 코드가 404로 남습니다. 서버를 건드리지 않으려면 4장 방법 A(쿼리스트링·HashRouter)로 앱을 바꾸는 것이 확실합니다.

7. 정리 — 고객 안내

결론: 새로고침 시 화면이 초기화되는 것은 React의 기본 동작이며, 화면 이동 시 주소가 바뀌지 않는 구조라 서버는 어떤 화면이었는지 알 수 없습니다. 서버 설정·버전과 무관하므로 앱에서 화면 상태를 주소 또는 sessionStorage에 저장하도록 수정해야 합니다.

고객에게 보낸 안내문 예시:

새로고침(F5) 시 보던 화면이 첫 화면으로 돌아가는 현상은 서버가 아닌
React 앱의 동작 방식 때문입니다.

- 현재 사이트는 메뉴를 이동해도 주소가 https://example.com/ 으로 그대로입니다.
- 새로고침할 때 서버가 받는 정보는 주소뿐이며, 보던 화면·페이지 번호 같은
  상태는 브라우저 메모리에만 있다가 새로고침 시 초기화됩니다.
- 따라서 서버 입장에서는 첫 접속과 새로고침이 같은 요청이라 서버 설정으로는
  화면을 유지할 수 없습니다. (curl 확인 결과 서버 응답 200 정상)

화면 유지를 위해 아래 중 한 가지로 앱 수정이 필요합니다.
 1) 화면 상태를 주소에 기록: /?view=list&page=3 또는 HashRouter(/#/list)
 2) 화면 상태를 sessionStorage에 저장 후 시작 시 복원
