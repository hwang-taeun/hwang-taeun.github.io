PAM 비밀번호 정책 설정 (authselect)

Rocky Linux 9의 authselect 관리 환경에서 비밀번호 복잡도, 최근 비밀번호 재사용 제한, 로그인 실패 잠금을 설정하고 검증한 방법입니다.

1. 적용 정책

항목정책PAM 모듈설정 파일
복잡도8자 이상, 대문자·소문자·숫자·특수문자 각 1개 이상pam_pwquality/etc/security/pwquality.conf
재사용 제한최근 4개 비밀번호 사용 금지pam_pwhistory/etc/security/pwhistory.conf
계정 잠금4회 연속 실패 시 10분 잠금pam_faillock/etc/security/faillock.conf

주요정보통신기반시설 취약점 점검 항목 중 패스워드 복잡성 설정(U-02)과 계정 잠금 임계값 설정(U-03)에 대응하는 설정입니다.

2. authselect 환경에서 주의할 점

RHEL·Rocky 9은 /etc/pam.d/system-auth와 password-auth를 authselect가 생성·관리합니다. 이 파일을 직접 고치면 다음 authselect 실행 때 덮어써지거나, authselect가 변경을 감지해 동작을 거부합니다. 그래서 PAM 모듈은 authselect 기능(feature)으로 켜고, 세부 값은 모듈별 .conf 파일에서 설정합니다.

3. authselect 기능 활성화 (faillock, pwhistory)

authselect select는 지정한 기능만 남기고 나머지는 끄므로, 기존에 켜져 있던 기능을 먼저 확인해 함께 적어야 합니다.

authselect current
# Profile ID: sssd
# Enabled features:
# - with-fingerprint
# - with-silent-lastlog

# 기존 기능 + faillock, pwhistory
authselect select sssd with-fingerprint with-silent-lastlog with-faillock with-pwhistory --force

--force는 예전에 PAM 파일을 직접 수정한 이력이 있어 authselect가 "예기치 않은 콘텐츠" 에러로 거부할 때 필요합니다. 이 경우 수정했던 내용은 사라지므로 미리 백업합니다.

4. 세부 정책 설정

모든 파일은 수정 전에 백업하고, 기존에 있던 같은 항목(주석 포함)을 지운 뒤 새로 추가해 중복 설정을 막습니다.

4.1 복잡도 (pwquality.conf)

FILE=/etc/security/pwquality.conf
cp -a $FILE ${FILE}.bak_$(date +%F)

sed -i -E '/^\s*#?\s*(minlen|dcredit|ucredit|lcredit|ocredit|enforce_for_root)\b/d' $FILE

cat >> $FILE << 'EOF'
minlen = 8
dcredit = -1
ucredit = -1
lcredit = -1
ocredit = -1
enforce_for_root
EOF
항목의미
minlen = 8최소 8자
dcredit / ucredit / lcredit / ocredit = -1숫자 / 대문자 / 소문자 / 특수문자 각각 최소 1개
enforce_for_rootroot가 비밀번호를 바꿀 때도 정책 강제 (기본은 경고만)

*credit 값이 음수이면 "해당 문자 종류를 최소 N개 포함"이라는 뜻입니다. 양수이면 길이 계산에 가산점을 주는 의미가 되어 필수 조건이 되지 않습니다.

4.2 재사용 제한 (pwhistory.conf)

FILE=/etc/security/pwhistory.conf
cp -a $FILE ${FILE}.bak_$(date +%F)

sed -i -E '/^\s*#?\s*remember\s*=/d; /^\s*#?\s*enforce_for_root\s*$/d' $FILE

cat >> $FILE << 'EOF'
remember = 4
enforce_for_root
EOF

4.3 로그인 실패 잠금 (faillock.conf)

FILE=/etc/security/faillock.conf
cp -a $FILE ${FILE}.bak_$(date +%F)

sed -i -E '/^\s*#?\s*deny\s*=/d; /^\s*#?\s*unlock_time\s*=/d' $FILE

cat >> $FILE << 'EOF'
deny = 4
unlock_time = 600
EOF

unlock_time = 600은 10분 뒤 자동 해제이고, 0이면 관리자가 풀 때까지 잠깁니다. 설정 파일 안의 주석은 값과 같은 줄에 쓰지 않고 별도 줄에 씁니다.

root 계정은 기본적으로 잠기지 않습니다(even_deny_root 미설정). 무차별 대입으로 root가 잠기면 콘솔 복구까지 막힐 수 있어 의도적으로 그대로 두고, root 원격 로그인은 SSH 설정(PermitRootLogin no)으로 따로 막습니다.

5. 적용 확인

authselect current

# PAM 에 모듈이 들어갔는지
grep -E "pam_faillock|pam_pwhistory|pam_pwquality" /etc/pam.d/system-auth

# 설정값이 한 줄씩만 있는지 (중복 없음)
grep -E "^(minlen|dcredit|ucredit|lcredit|ocredit|enforce_for_root)" /etc/security/pwquality.conf
grep -E "^(remember|enforce_for_root)"  /etc/security/pwhistory.conf
grep -E "^(deny|unlock_time)"           /etc/security/faillock.conf

6. 동작 테스트

# 복잡도: 비밀번호를 실제로 바꾸지 않고 정책 통과 여부만 확인
echo 'abc1234'      | pwscore      # 거부: 길이 부족, 대문자·특수문자 없음
echo 'Abcd1234'     | pwscore      # 거부: 특수문자 없음
echo 'Abcd!2345xyz' | pwscore      # 통과: 점수 출력

# 실제 변경 시도 (정책 위반 비밀번호는 거부되는지)
passwd testuser

# 잠금: 다른 터미널에서 testuser 로 4회 틀리게 로그인한 뒤
faillock --user testuser
# testuser:
# When                Type  Source           Valid
# 2026-11-17 10:12:01 RHOST 10.0.0.2         V
# ... (4건)

# 관리자 잠금 해제
faillock --user testuser --reset

재사용 제한은 같은 계정으로 최근 4개 중 하나를 다시 입력해 Password has been already used가 나오는지 확인합니다.

7. 트러블슈팅

증상원인 및 해결
authselect select가 거부됨PAM 파일을 직접 수정한 이력 → 백업 후 --force
기존 기능(지문 로그인 등)이 꺼짐authselect select에 기존 기능을 함께 적지 않음 → authselect current로 확인 후 다시 적용
설정을 넣었는데 적용 안 됨같은 항목이 파일에 두 번 있음(아래 줄 우선) → grep으로 중복 확인
root 비밀번호는 약해도 바뀜pwquality 기본값은 root에게 경고만 함 → pwquality.conf에 enforce_for_root
사용자가 계속 잠김스크립트·서비스가 옛 비밀번호로 반복 로그인 → faillock --user의 Source로 출발지 확인
