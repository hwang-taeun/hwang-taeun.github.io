SPF 메일 인증 절차

SPF 레코드로 메일을 검증하는 과정을 정상 메일, 스팸 메일, 피싱 메일에 적용해 정리했습니다.

1. 전제 조건

example.com 도메인의 SPF 레코드가 다음과 같이 설정되어 있다고 가정합니다.

example.com.    IN  TXT  "v=spf1 include:spf.example.com -all"
  • include:spf.example.com: spf.example.com의 SPF 레코드에 등록된 서버를 발송 허용 서버로 포함합니다.
  • -all: 위 목록에 없는 서버에서 보낸 메일은 모두 실패(Fail)로 처리합니다. ~all은 약한 실패(SoftFail)로, 거부 대신 스팸함으로 분류하는 경우가 많습니다.
  • SPF는 메일 본문의 From: 헤더가 아니라, SMTP 전송 시 사용한 발신 주소(MAIL FROM, Return-Path)의 도메인을 기준으로 검사합니다.

→ DNS 레코드 정리 (TXT 레코드)

2. 정상 메일

조건

  • 발신 주소: user@example.com
  • 발신 서버 IP: 192.0.2.1 (spf.example.com에 등록된 IP)

과정

  1. 사용자가 user@example.com으로 메일을 발송합니다.
  2. 수신 메일 서버가 example.com의 DNS에서 SPF 레코드를 조회합니다.
  3. 192.0.2.1은 include로 포함된 허용 서버이므로 SPF 검증에 성공(Pass)합니다.
  4. 메일이 정상적으로 수신자에게 전달됩니다.

3. 스팸 메일 (발신 도메인 위장)

조건

  • 발신 주소: user@example.com (위장)
  • 발신 서버 IP: 198.51.100.1 (spf.example.com에 등록되지 않은 IP)

과정

  1. 스팸 발송자가 user@example.com으로 위장해 메일을 발송합니다.
  2. 수신 메일 서버가 example.com의 DNS에서 SPF 레코드를 조회합니다.
  3. 198.51.100.1은 허용 목록에 없으므로 SPF 검증에 실패(Fail)합니다.
  4. -all 정책에 따라 메일이 거부되거나 스팸으로 분류됩니다.

4. 피싱 메일 (다른 도메인으로 발송)

조건

  • 실제 발신 주소(MAIL FROM): user@malicious.com
  • 화면에 보이는 발신자(From:): example.com으로 위장
  • 발신 서버 IP: 203.0.113.1 (malicious.com의 서버)
  • malicious.com의 SPF 레코드: "v=spf1 ip4:203.0.113.1 -all"

과정

  1. 공격자가 자신이 소유한 malicious.com으로 메일을 보내면서, 수신자에게는 example.com에서 온 것처럼 보이게 합니다.
  2. 수신 메일 서버는 MAIL FROM 도메인인 malicious.com의 SPF 레코드를 조회합니다.
  3. 203.0.113.1은 malicious.com의 허용 서버이므로 SPF 검증 자체는 성공합니다. SPF만으로는 이 위장을 막을 수 없습니다.
  4. 수신 서버는 DMARC로 추가 검증합니다. From: 도메인(example.com)과 SPF·DKIM으로 인증된 도메인(malicious.com)이 일치하지 않으므로 DMARC 검증에 실패합니다.
  5. example.com의 DMARC 정책(p=quarantine 또는 p=reject)에 따라 메일이 격리되거나 거부됩니다.

5. 정리: SPF · DKIM · DMARC

  • SPF: 메일을 보낸 서버가 해당 도메인에서 허용한 서버인지 검증합니다.
  • DKIM: 메일에 전자서명을 붙여, 발송 도메인과 내용이 전송 중에 위·변조되지 않았는지 검증합니다.
  • DMARC: 화면에 보이는 From: 도메인이 SPF·DKIM 인증 결과와 일치하는지 확인하고, 실패한 메일의 처리 정책과 보고 주소를 지정합니다.

SPF는 발송 서버를 검증하는 첫 단계입니다. DKIM, DMARC와 함께 사용할 때 스팸과 피싱을 가장 효과적으로 막을 수 있습니다.

레코드 확인 명령

# SPF 레코드 확인
dig +short TXT example.com

# DMARC 레코드 확인
dig +short TXT _dmarc.example.com

# DKIM 공개키 확인 (selector는 메일 헤더의 s= 값)
dig +short TXT selector._domainkey.example.com
